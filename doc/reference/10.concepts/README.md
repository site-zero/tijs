# 核心概念机制

## TiJS 要解决的是什么

用 Vue 3 搭过页面的人都熟悉这个过程：放按钮、输入框、表格，样式自己调；只读、占位、
显隐、多语言在每个组件里各写一遍。页面一多，颜色和尺度开始不统一，同样的判断逻辑在不
同控件里重复出现。

TiJS 是一套 Vue 3 Web UI 控件库。它最朴素的初衷，就是**让你在只保留少量 HTML/CSS
常识的前提下，搭出一个样式统一、行为一致的合格界面**：色彩、圆角、间距、字号、亮暗
主题由样式体系统一提供；只读、占位、显隐、前后缀、悬浮提示由共享机制统一处理；开发时
把精力放在"页面由哪些控件组成、数据如何流转"上，而不是逐个控件打磨原生细节。

## 定位：不只服务于管理后台

和以信息系统后台为中心的控件库不同，TiJS 不把自己限定在管理后台场景。目前内置 72 个
可用组件（另有 3 个已标记弃用、不再收录进文档），规划继续扩充到 100+，希望覆盖三类界面：

- **管理后台**：复杂表单、复杂表格、筛选与编辑；
- **PC 网页**：商城、官网、内容页等更开放的排版场景；
- **窄屏场景**：受限于宽度的输入与展示形态。

控件数量只是表层。围绕这些场景，TiJS 同时在几个横向上投入设计：

- **更好的 I18n 支持**：核心文案与组件局部文案分层管理，组件配置本身携带语言包，可在
  运行时切换语言；
- **复杂表单与复杂表格**：提供字段、列的集中注册与管理机制，用很少的代码组织庞大表单
  或表格；
- **日历视图**：日历、周视图、时间段等专用控件与配套机制；
- **可复用钩子**：把只读、选项、校验、拖拽、值规整等能力提炼成 composable，既供内置
  组件使用，也帮你构建自己的组件。

## 几条特殊的设计取向

除了提供控件本身，TiJS 还有几条和传统组件库不太一样的取向，后面的机制篇会反复回到
它们：

- **控件配置对 JSON 友好**：组件行为尽量用一份 `comConf`（普通对象）描述，而不是只能在
  模板里命令式调用；这同时让所见即所得编辑器、schema 动态渲染更容易实现。
- **为动态数据提出"字典"模型**：下拉、单选、多选等选项型控件，选项可以是静态数组、
  远程查询、上下文相关的动态集合；值到文本、图标、提示的翻译由统一字典完成。
- **表单与表格字段集中管理**：字段与列先注册成标准定义，界面再按定义组装，避免在每个
  页面里重复声明同类控件的配置。

TiJS 里看到的每一套机制，都是在为上面这些目标服务。读概念篇时不妨不断回到这一节对照：
这个机制解决的是哪一条目标。

## 目标对应到下面六篇机制

```text
                         业务应用
                            │
                ┌───────────┼────────────┐
                │           │            │
          组件模型      共享 Props      事件绑定
        (TiComInfo)   (CommonProps…)  (emits / adaptor)
                │           │            │
                └─────┬─────┴─────┬──────┘
                      │           │
                 国际化 i18n    样式体系
                      │           │
                      └─────┬─────┘
                            │
                      字典模型（选项型控件专用）
```

- **组件模型**回答"配置友好"：一个控件用一份描述对象（`TiComInfo`）集中记录分类、
  名称、语言包、默认示例、事件清单，应用启动统一注册，运行时按类型名查找。
- **共享 Props** 回答"少重复"：只读、占位、显隐、前后缀、提示、停靠等横切能力收敛成
  统一 Props 与 hook，不要求每个组件各自实现。
- **事件绑定**回答"配置与动态渲染"：标准 `emit` 之外提供事件适配器；`exampleModel`
  规定事件载荷如何回写配置，让演示与配置面板能够实时反映控件状态。
- **国际化 i18n** 直接对应"更好的 I18n 支持"：核心包与组件局部包分层并入，`i18n:`
  前缀贯穿配置与文案。
- **样式体系**回答"少碰 CSS"：颜色、尺度、主题、布局 mixin 全部变量化，切换亮暗与密度
  只需切换顶层类名。
- **字典模型**直接对应"动态数据"：静态数组、远程查询、动态上下文统一成一套字典接口，
  供选项型控件消费。
